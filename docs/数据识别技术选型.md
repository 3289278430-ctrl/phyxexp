# 数据识别技术选型（开源）

> 目标：让 phyxexp 能从扫描件/拍照的表格（含手写）里自动抽出数据并映射到实验。
> 结论：**文字 OCR + 表格结构识别 + 手写识别**三件事分开解决，全部有成熟开源方案。

## 要解决的三个子问题
1. **文字 OCR**：把图片里的字（含中文标签、数字）变成文本。
2. **表格结构**：识别哪是表头、哪是行列、哪一列是 x / y、单位是什么。
3. **手写数字**：实验数据常是手写，是 OCR 最难的一类（8↔3、0↔6 常认错）。

## 候选开源技术（按推荐度）

| 技术 | 解决什么 | 特点 | 链接 |
|---|---|---|---|
| **PaddleOCR + PP-Structure**（百度）| 文字+表格结构+公式+手写+关键信息 | 中文最强，PP-Structure 专做文档/表格/公式 | https://github.com/PaddlePaddle/PaddleOCR |
| **RapidOCR / RapidAI** | 文字 OCR（PaddleOCR 的 ONNX 轻量版）| 轻量、免 paddle、已内置为默认后端 | https://github.com/RapidAI/RapidOCR |
| **Surya 2** | 多语言 OCR + 表格识别 | PyTorch，表格行列识别准 | https://github.com/VikParuchuri/surya |
| **TableTransformer**（微软）| 表格结构（单元格/行列检测）| 与任意 OCR 搭配 | https://github.com/microsoft/table-transformer |
| **Marker** | PDF → Markdown（表格/公式/图片）| 整篇文档结构化 | https://github.com/VikParuchuri/marker |
| **DocTR**（Mindee）| 文档文字/表格抽取 | 端到端 | https://github.com/mindee/doctr |
| **TrOCR**（微软）| Transformer OCR（可微调手写）| 手写场景可微调 | https://huggingface.co/microsoft/trocr-base-handwritten |

## 推荐架构（phyxexp 数据识别层，可插拔）

\`\`\`
文档(PDF/图片)
   │  ①识别后端（可插拔）
   │    默认 RapidOCR（轻量，已内置）
   │    升级 PaddleOCR PP-Structure / Surya / TableTransformer（表格结构+手写）
   ▼
表格（结构 + 文字 + 置信度）
   │  ②语义映射
   │    config/experiments.json 目录（标签+单位+keywords）
   │    + 宿主 LLM 上下文（聊天记忆 / 文件名 / 用户说过的话）
   ▼
实验输入 → scripts/run.py --auto → 受约束计算
\`\`\`

关键原则：**识别后端可换、计算层不动**。识别出的表再交给 identify/auto 映射到实验，数值仍由白名单工具链计算。

## 为什么手写最难 + 怎么解
- 通用文字 OCR 对手写数字错误率高（本轮实测：手写表 110 个框被切成 47 行，数字被拆散）。
- 解法：PP-Structure 的**表格结构**先框定单元格，再用 PaddleOCR **手写识别**模型逐格识别；或 TrOCR 微调手写数字。
- 长期：识别结果带**置信度**反馈给宿主 LLM，低置信度处由 LLM 用上下文（如"这是杨氏模量，直径那列单位是 mm"）补正。
